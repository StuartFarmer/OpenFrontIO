# S3.2: Wrap OpenFront HUD Composition

**Status**: DONE
**Wave**: W3
**Track**: HUD
**Supports**: D3
**Effort**: M
**Dependencies**: S3.1

## Purpose

Make the current HUD/controller composition explicitly OpenFront-owned without changing the composition.

This is a placement/ownership change only: the same custom elements,
controllers, and layer order should remain wired for OpenFront.

## Scope

- In: `createRenderer()` placement/naming, OpenFront HUD custom element wiring, OpenFront controller list.
- Out: Feature toggles, optional HUD matrix, Foundation HUD.
- Boundary: keep generic `GameRenderer` as a renderer/layer ticker, and move OpenFront-specific HUD composition into the OpenFront client package.

## Touchpoints

- Create: `src/games/openfront/client/OpenFrontHud.ts`
- Modify: `src/client/hud/GameRenderer.ts`
- No compatibility re-export from the old path; update the OpenFront mount path directly.

## Acceptance Criteria

- [x] OpenFront HUD composition still wires all current elements and controllers.
- [x] The module boundary makes clear this HUD is OpenFront-specific.
- [x] No feature flags are introduced to hide OpenFront HUD pieces for other games.
- [x] `GameRenderer` no longer owns OpenFront element/controller selection; it only manages initialized layers and ticks.
