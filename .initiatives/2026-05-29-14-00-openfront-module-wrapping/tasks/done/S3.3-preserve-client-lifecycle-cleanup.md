# S3.3: Preserve Client Lifecycle Cleanup

**Status**: DONE
**Wave**: W3
**Track**: Client Lifecycle
**Supports**: D3, D5
**Effort**: M
**Dependencies**: S3.1

## Purpose

Ensure module wrapping does not regress cleanup, reconnect, stop, replay, save-game, or WebGL disposal behavior.

The wrapper should keep `ClientGameRunner.stop()` as the authoritative stop
path for a mounted OpenFront runtime, with the OpenFront module providing the
DOM/WebGL/input cleanup callback created during mount.

## Scope

- In: `ClientGameRunner.stop()`, worker cleanup, transport leave, DOM cleanup, WebGL disposal, sound disposal, intervals/timeouts.
- Out: Redesigning transport reconnect semantics.
- Boundary: lifecycle behavior may be tested with fakes, but production cleanup should still flow through the real runner and module-created cleanup callback.

## Touchpoints

- Modify: `src/client/ClientGameRunner.ts`
- Potentially Modify: `src/games/openfront/client/OpenFrontClientModule.ts`
- Potentially Create: lifecycle tests.

## Acceptance Criteria

- [x] Stopping an OpenFront game disposes worker, transport, sound, WebGL, input overlay, and intervals as before.
- [x] `shouldPreventWindowClose()` remains based on OpenFront active player state.
- [x] Save-game behavior for OpenFront win updates remains unchanged.
- [x] Stopping before the delayed connection-check interval starts does not leave a later reconnect loop behind.
