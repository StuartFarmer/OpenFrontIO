## Purpose

Pin minimal valid generic envelope examples before OpenFront adapters or worker migration depend on them.

## Alignment

- Initiative goal: Prove generic protocol envelopes can carry module-owned payloads without OpenFront dependencies.
- Deliverable: D1 Engine Protocol Contracts.
- Demo check: `npm test -- tests/core/protocol`.
- Wave rationale: Tests lock the baseline contract before bridge and worker migration waves consume it.

## Scope

- In:
  - Add unit tests for generic start, turn, intent, update, module event, and error envelope examples.
  - Cover map delta buffers and metrics.
  - Assert `moduleId` naming in start and update envelopes.
- Out:
  - No OpenFront payload validation.
  - No Foundation runtime implementation.
  - No bridge, worker, replay, or renderer changes.

## Context and Rationale

- Why this exists: Future runtime and bridge work needs a stable envelope boundary with examples.
- Constraints: Tests may only touch protocol files and must not require OpenFront game setup.
- Trade-offs: Tests validate generic envelope shape, not gameplay semantics.
- Chosen approach: Use small Vitest examples with Zod `safeParse` and transfer buffer assertions.

## Behavior and Requirements

### B1: Unknown config and intent payloads

- Given: Start and turn envelopes with arbitrary module payloads.
- When: The protocol schemas validate them.
- Then: Validation succeeds without importing or asserting OpenFront payload fields.

### B2: Update events, metrics, and map deltas

- Given: An update envelope with module events, metrics, and typed-array map deltas.
- When: The protocol schema validates it and transferables are collected.
- Then: Validation succeeds and the typed array buffers are available for transport.
