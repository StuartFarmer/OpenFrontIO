## Purpose

Expose controlled access to current game state and side-effect services for
systems.

## Scope

- In: Context for game, config, players, attacks, units, updates, stats,
  randomness, tick, and command enqueueing.
- Out: Rewriting `GameImpl`, `PlayerImpl`, or `UnitImpl` storage.

## Touchpoints

- Create: `src/core/systems/GameSystemContext.ts`
- Modify: `src/core/game/GameImpl.ts` as needed to construct context.

## Acceptance Criteria

- [x] Systems can access required state through a typed context.
- [x] Write paths are explicit and compatible with current domain objects.
