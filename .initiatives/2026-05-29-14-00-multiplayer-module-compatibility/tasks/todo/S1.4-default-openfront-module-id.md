## Purpose
Make the OpenFront default explicit so old messages, old archives, and old lobby configs are not broken by `moduleId`.

## Scope
- In: Shared constant for default module id.
- In: Compatibility tests for missing `moduleId`.
- Out: Adding a full module registry.

## Touchpoints
- Create: `src/core/modules/ModuleIds.ts` or equivalent.
- Modify: Protocol adapters and schema tests.

## Acceptance Criteria
- [ ] Default module id is a single shared constant.
- [ ] Old OpenFront configs do not need migration before parsing.
- [ ] New non-OpenFront configs must specify module identity through the generic path.

## Test Plan
- `legacy_config_resolves_to_openfront_module` - confirms old behavior.
- `generic_config_keeps_declared_module_id` - prevents accidental defaulting.
