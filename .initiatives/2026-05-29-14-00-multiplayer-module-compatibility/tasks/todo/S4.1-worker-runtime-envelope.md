## Purpose
Separate generic worker init/turn/update processing from OpenFront-specific `GameRunner` and query messages.

## Scope
- In: Generic worker init message with module start envelope.
- In: Generic worker turn message with module turn envelope.
- In: Module runtime lookup during worker init.
- Out: Rewriting OpenFront `GameRunner`.

## Touchpoints
- Modify: `src/core/worker/WorkerMessages.ts`.
- Modify: `src/core/worker/Worker.worker.ts`.
- Modify: `src/core/worker/WorkerClient.ts`.
- Create: Module worker runtime interface under `src/core/modules` or `src/core/worker`.

## Acceptance Criteria
- [ ] Worker can initialize a module runtime through the registry and default services boundary.
- [ ] OpenFront worker init still reaches current `createGameRunner()` through an adapter.
- [ ] Turn drain scheduling remains bounded by the existing yield/backlog behavior.
