# S3.3: Foundation Camera And Input

**Status**: DONE
**Wave**: W3
**Track**: B
**Supports**: D4
**Effort**: Medium
**Dependencies**: S3.1

## Purpose

Plan a Foundation-owned input path for camera movement and click-to-place without using OpenFront `InputHandler`.

## Scope

- In: Renderer-side camera fit/get/set and screen-to-tile conversion from screen coordinates.
- Out: DOM input overlay creation, OpenFront radial menu, build menu, emoji menu, warship selection, attack ratios, alliances, pause/game-speed keybinds, or module route wiring.

## Touchpoints

- Modify: `src/client/render/base-map/BaseMapWebGLAdapter.ts`.
- Create/update tests under `tests/client/render/base-map/`.

## Acceptance Criteria

- [x] Click-to-place emits a Foundation event/intent with tile ref and screen/world coordinates.
- [x] Camera can fit the map and support minimal pan/zoom behavior.
- [x] Foundation input code has no dependency on OpenFront `UIState`.
- [x] Screen-to-tile returns `null` outside map bounds and uses row-major tile refs.

## Test Plan

- `base-map-adapter.test.ts` - verifies `screenToTile`, `screenToWorld`, `fitMap`, `getCameraState`, and `setCameraState` via a fake target.

## Working Notes

- DOM event wiring remains for a future Foundation module ticket; this ticket keeps the renderer-side conversion ready.
- Added renderer-side `screenToWorld()` and `screenToTile()` conversion.
- Added camera `fitMap()`, `getCameraState()`, and `setCameraState()` wrapper methods.
- No OpenFront `InputHandler` or `UIState` dependency was introduced.
