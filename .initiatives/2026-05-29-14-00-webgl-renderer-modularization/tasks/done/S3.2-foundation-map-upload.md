# S3.2: Foundation Map Upload

**Status**: DONE
**Wave**: W3
**Track**: A
**Supports**: D4
**Effort**: Medium
**Dependencies**: S3.1

## Purpose

Plan the data flow for Foundation to upload blank terrain and ownership state through the base renderer contract.

## Scope

- In: Raw terrain bytes, owner palette entries, full tile-state upload, changed tile updates, and helper logic for fixed-radius owner placement.
- Out: Terrain semantics, resource yields, population/food, complex terrain materials, or module/runtime integration.

## Touchpoints

- Create: `src/client/render/base-map/TileState.ts`.
- Modify: `src/client/render/base-map/BaseMapWebGLAdapter.ts`.

## Acceptance Criteria

- [x] Blank terrain uses raw terrain bytes and does not depend on OpenFront map assets.
- [x] Ownership writes use the owner-id bits in the tile-state buffer and ignore OpenFront fallout/defense bits.
- [x] Fixed-radius claim can upload changed tile refs/states without a full frame rebuild.
- [x] Full and delta uploads validate `width * height` buffer lengths before dispatch.

## Test Plan

- `base-map-adapter.test.ts` - verifies full/delta dispatch and terrain delta dispatch with a fake target.
- `tile-state.test.ts` - verifies owner low-12-bit encoding and fixed-radius deltas.

## Working Notes

- Keep owner encoding compatible with `OWNER_MASK` from `src/client/render/gl/utils/TileCodec.ts`.
- Added tile-state helpers and adapter upload methods for full tile state, tile deltas, terrain deltas, and palette updates.
- `claimRadius()` preserves non-owner bits and dispatches only changed tile-state deltas.
