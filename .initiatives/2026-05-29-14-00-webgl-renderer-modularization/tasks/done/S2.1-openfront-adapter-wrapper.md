## Purpose

Make the current OpenFront WebGL path explicit as an OpenFront adapter while preserving behavior.

## Scope

- In: Naming/wrapping `WebGLFrameBuilder` and `uploadFrameData()` as the OpenFront compatibility path from a new renderer-owned adapter namespace.
- Out: Editing `ClientGameRunner`, route files, OpenFront module mount code, or changing the live WebGL setup.
- Out: Rewriting `FrameData`, `GameView`, pass construction, HUD mounting, replay behavior, or OpenFront input behavior.

## Touchpoints

- Create: `src/client/render/base-map/OpenFrontCompatibilityAdapter.ts`.
- Modify: Existing OpenFront files only if unavoidable; the intended implementation is additive.

## Acceptance Criteria

- [x] OpenFront still constructs the same WebGL canvas and renderer.
- [x] `WebGLFrameBuilder.update(gameView)` still syncs players, local player, spawn overlay, terrain deltas, and full frame upload.
- [x] Any new wrapper makes clear that OpenFront frame data is not the base renderer contract.
- [x] The wrapper does not introduce Foundation dependencies into OpenFront frame upload code.
