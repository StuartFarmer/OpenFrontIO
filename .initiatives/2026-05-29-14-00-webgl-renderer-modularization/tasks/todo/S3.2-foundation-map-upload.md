## Purpose
Plan the data flow for Foundation to upload blank terrain and ownership state through the base renderer contract.

## Scope
- In: Blank grass terrain bytes, owner palette entry, full tile-state upload, changed tile updates for fixed-radius placement.
- Out: Terrain semantics, resource yields, population/food, complex terrain materials.

## Touchpoints
- Create: Future Foundation map render frame/update helper.
- Modify: Existing WebGL facade only through minimal base target adapter if needed.

## Acceptance Criteria
- [ ] Blank terrain uses raw terrain bytes and does not depend on OpenFront map assets.
- [ ] Ownership writes use the owner-id bits in the tile-state buffer and ignore OpenFront fallout/defense bits.
- [ ] Fixed-radius claim can upload changed tile refs/states without a full frame rebuild.
