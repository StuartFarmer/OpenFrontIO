# S2.1: Player Execution Resource Regen

**Status**: DONE
**Wave**: W2
**Track**: Tick integration
**Supports**: D3
**Effort**: Medium
**Dependencies**: W1
**Hardened**: 2026-05-21

## Purpose

Switch passive resource accumulation in `PlayerExecution` from old `goldAdditionRate(...)` mirroring to `resourceIncreaseRate(...)`.

## Scope
- In: Passive resource tick path, `{ updateGold: false }` mutation, stats compatibility decision.
- Out: Trade, train, conquest, donation, terrain production.

## Context and Rationale
- Why this exists: W1 added config resource regen; this ticket moves the live passive tick path onto that model.
- Constraints: Passive resource income must not mutate gold, and troop regen must stay untouched.
- Trade-offs: Existing `goldWork` stats remain compatibility stats until a separate stats migration.
- Chosen approach: Call `config.resourceIncreaseRate(player)` in `PlayerExecution` and apply it through `addResources(..., { updateGold: false })`.

## Behavior and Requirements
### B1: Passive resources use config regen
- Given: an alive player with territory.
- When: `PlayerExecution` ticks.
- Then: resource stockpiles increase by `config.resourceIncreaseRate(player)`.

### B2: Passive resources do not add gold
- Given: a player receives passive resource regen.
- When: the tick completes.
- Then: `player.gold()` remains unchanged.

### B3: Existing troop path remains stable
- Given: a player tick.
- When: resource regen changes.
- Then: `config.troopIncreaseRate(player)` still drives troop increase.
