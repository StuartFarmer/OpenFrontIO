# S1.2: Config Resource Capacity

**Status**: DONE

**Dependencies**: S1.1
**Hardened**: 2026-05-21

## Purpose

Expose resource capacity and passive regen formulas from `Config`, modeled after `maxTroops(...)` and `troopIncreaseRate(...)`.

## Scope
- In: `maxResources(player)`, `resourceIncreaseRate(player)`, area baseline, completed Factory-level storage contribution.
- Out: Changing troop formulas, changing Factory costs, changing resource spending.

## Context and Rationale
- Why this exists: The tick path should ask config for capacity/regen rather than hard-code economy math in `PlayerExecution`.
- Constraints: `Config` is used by both core `Player` and client `PlayerView`, so formulas must rely on common player/view methods.
- Trade-offs: The first implementation keeps Food, Energy, and Materials on the same formula; resource differentiation belongs in a later terrain/resource-production slice.
- Chosen approach: Add resource methods near the troop methods so the relationship is obvious and future balancing stays centralized.

## Behavior and Requirements
### B1: Area baseline
- Given: a player with more controlled tiles.
- When: `maxResources(player)` is computed.
- Then: all three resource capacities increase.

### B2: Factory storage
- Given: a player with completed Factory levels.
- When: `maxResources(player)` is computed.
- Then: all three resource capacities include Factory storage.

### B3: Under-construction exclusion
- Given: a Factory that is still under construction.
- When: `maxResources(player)` is computed.
- Then: that Factory does not increase resource capacity.

### B4: Regen formula
- Given: a player with current resources below capacity.
- When: `resourceIncreaseRate(player)` is computed.
- Then: it returns a resource-shaped passive delta using the same curve helper as S1.1.
