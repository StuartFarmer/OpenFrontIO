# S3.1: Resource Capacity Update State

**Status**: DONE
**Wave**: W3
**Track**: Client state
**Supports**: D4
**Effort**: Medium
**Dependencies**: W1

## Purpose

Carry resource capacity through worker/client player updates and expose it from `PlayerView`.

## Scope
- In: `PlayerUpdate.resourceCapacity`, diff/apply support, renderer state, `PlayerView.resourceCapacity()`.
- Out: Replay schema redesign, removing gold fields, capacity UI layout.

## Context and Rationale
- Capacity must be sent from the simulation because it depends on live ownership and completed Factory state.
- The client already receives `resources` as a `ResourceStockpile`; `resourceCapacity` should use the same shape to avoid a parallel schema.
- Partial update behavior should mirror `resources`: omit the field when all three values are unchanged, include the full stockpile when any value changes.
