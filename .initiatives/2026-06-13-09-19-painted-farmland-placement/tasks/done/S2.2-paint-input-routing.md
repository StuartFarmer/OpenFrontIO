# S2.2: Paint Input Routing

**Status**: DOING
**Wave**: W2
**Track**: Client
**Supports**: D3
**Effort**: M
**Dependencies**: S2.1

## Purpose

Route pointer down/move/up differently while paint mode is active so hold-to-paint works and normal drag behavior remains intact outside paint mode.

## Scope

- In: Paint stroke start, move, end events; drag suppression during active paint stroke; pointer cleanup on blur/cancel.
- Out: Core Farmland validation and bottom UI.

## Touchpoints

- Create: Paint-specific input events if cleaner than reusing `MouseUpEvent`.
- Modify: `src/client/InputHandler.ts`, `src/client/controllers/BuildPreviewController.ts` or a new paint placement controller.

## Acceptance Criteria

- [x] Pointer down in paint mode starts a stroke and attempts placement at the current tile.
- [x] Pointer movement during a stroke does not pan the camera.
- [x] Pointer up ends the stroke but keeps Farmland selected.
- [x] Non-paint pointer behavior remains unchanged.

## Test Plan

- `test_paint_drag_consumes_camera_drag` - paint stroke does not emit normal drag.
- `test_non_paint_drag_still_pans` - existing drag behavior remains intact.

## Working Notes

- Planning baseline created.
- Added `PaintStrokeStartEvent`, `PaintStrokeMoveEvent`, and `PaintStrokeEndEvent`.
- `InputHandler` emits paint stroke events while a paintable unit is selected and suppresses normal drag for the active paint stroke.
- Pointer-up ends only the stroke and leaves `uiState.ghostStructure` selected.
- Verified with `npx tsc --noEmit`.
