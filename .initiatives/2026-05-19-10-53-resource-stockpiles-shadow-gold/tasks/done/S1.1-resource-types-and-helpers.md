# S1.1: Resource Types And Helpers

**Status**: DONE
**Wave**: W1
**Track**: Core model
**Supports**: D1
**Effort**: Small
**Dependencies**: None

## Purpose

Define the minimal resource domain model used by the rest of the compatibility layer.

This ticket establishes names and helper behavior only. The resource stockpile does not become a gameplay mechanic until later tickets wire it into `PlayerImpl` and acquisition paths.

## Scope
- In: Add Food, Energy, Materials type definitions, a canonical list of resource kinds, and helper(s) for converting scalar gold amounts to equal resource payloads.
- In: Keep helper behavior deterministic and allocation-safe enough for repeated economy calls.
- Out: Terrain production, resource-specific costs, UI rendering, player storage, update serialization.

## Touchpoints
- Create: `src/core/game/Resources.ts`
- Modify: `src/core/game/Game.ts` only if re-exporting or colocating is needed.

## Acceptance Criteria
- [x] `ResourceKind`, `ResourceAmount`, `ResourceStockpile`, and `ResourceDelta` are exported from core resource code.
- [x] A canonical `ResourceKinds` list contains `food`, `energy`, and `materials`.
- [x] `resourcesFromGoldAmount(100n)` returns `{ food: 100n, energy: 100n, materials: 100n }`.
- [x] Resource copy/add/subtract helpers are available if needed by `PlayerImpl` without exposing mutable shared objects.
- [x] Helper names make clear this is a compatibility conversion from old gold value.

## Test Plan
- `resourcesFromGoldAmount` - verifies equal resource payload output.
- `resource helper immutability` - verifies callers can mutate returned objects without changing canonical zero/default state.
- `resource type compile check` - covered by TypeScript and later player-resource tests.
