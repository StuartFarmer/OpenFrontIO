## Purpose

Document how contributors install mdBook and use the repository docs commands without adding Rust tooling to the game runtime.

## Scope
- In: Add contributor-facing docs for pinned mdBook install, build, serve, and troubleshooting.
- Out: CI install automation and docs publishing.

## Touchpoints
- Create: `docs/src/development/docs-workflow.md` or equivalent
- Modify: `README.md` or `CONTRIBUTING.md` only if a top-level pointer is needed
- Modify: `docs/src/SUMMARY.md`

## Acceptance Criteria
- [ ] The docs workflow names the pinned mdBook version.
- [ ] macOS Homebrew and Cargo install paths are documented without making either mandatory.
- [ ] The workflow distinguishes `docs:generate`, `docs:check`, `docs:build`, and `docs:serve` responsibilities, even if generation lands in W2.
