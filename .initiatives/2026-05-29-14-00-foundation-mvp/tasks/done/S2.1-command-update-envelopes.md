# S2.1: Command And Update Envelopes

**Status**: DONE
**Wave**: W2
**Track**: Runtime
**Supports**: D3
**Effort**: Medium
**Dependencies**: W1

## Purpose

Define small Foundation-owned command and update envelopes that follow the parent generic protocol direction without modifying global OpenFront schemas.

This ticket establishes only the transport-facing runtime shape for the Foundation MVP. It should make click placement expressible as a module-owned command and make placement results observable as a Foundation-native update envelope carrying changed tile refs and states for the renderer adapter.

## Scope

- In: Foundation command payloads, placement command, update envelope, map delta fields, module event fields, error/result types if needed.
- Out: Shared `src/core/Schemas.ts` migration, OpenFront bridge, multiplayer server protocol.
- Out: Runtime mutation logic, worker transport, population/food commands, OpenFront `Intent` or `GameUpdateViewData` compatibility.

## Acceptance Criteria

- [x] Placement command is Foundation-owned and does not use OpenFront `Intent`.
- [x] Update envelope separates map/tile updates from module events.
- [x] Envelope fields preserve a future worker/multiplayer path: module id, tick, command payload, update payload, metrics if useful.
- [x] Types are narrow enough for the MVP and do not predefine population/food commands.
- [x] Map delta shape can report changed tile refs and corresponding tile state values without requiring a full state buffer.
