# S2.2: Local Runtime Command Router

**Status**: TODO
**Wave**: W2
**Track**: Runtime
**Supports**: D3
**Effort**: Medium
**Dependencies**: S2.1, W1

## Purpose
Implement a local single-player Foundation runtime that processes placement commands, mutates Foundation state, advances ticks, and emits updates.

## Scope
- In: runtime state, command dispatch, placement command execution, tick/update count, map changed-tile reporting.
- Out: Worker integration, network transport, deterministic auto-start placement, population/food systems.

## Touchpoints
- Create: `src/games/foundation/runtime/FoundationRuntime.ts`
- Create: `src/games/foundation/runtime/FoundationCommandRouter.ts`
- Modify: Foundation domain files only if placement API needs adjustment.

## Acceptance Criteria
- [ ] Runtime initializes a blank Foundation world with one unplaced player.
- [ ] Runtime accepts one click placement command and produces ownership tile deltas.
- [ ] Runtime does not install OpenFront spawn timer, win check, rails, bots, nations, or executions.
- [ ] Runtime records enough state for the debug panel: tick/update count, selected tile, claimed tile count, placement status.

## Test Plan
- `foundation_runtime_places_player_from_command` - validates command routing to placement domain.
- `foundation_runtime_emits_map_delta_update` - validates update contains changed tile refs/states.
- `foundation_runtime_rejects_or_ignores_second_place_explicitly` - validates repeated placement policy.

## Working Notes
- Keep the class/function shape transport-neutral so a later worker can call the same runtime from message handlers.
