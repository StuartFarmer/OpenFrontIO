# S4.2. Clan Components

## Deliverable

D5. Settings, Clan, Leaderboard, Ranking, And Stats Migration

## Objective

Migrate clan screens to shared surface, table/list, form, and modal primitives while preserving clan workflows.

## Scope

Review and migrate:

- `src/client/components/ClanModal.ts`
- `src/client/components/ClanShared.ts`
- `src/client/components/clan/*`

## Acceptance Criteria

- Clan data display, actions, forms, and navigation are unchanged.
- Tables/lists use shared primitives for consistent spacing and states.
- Loading and empty states are explicit and reusable.

## Validation

```bash
npx tsc --noEmit
npx vitest run tests/client/components/UiComponents.test.ts
npx vitest run tests/client/clan/ClanShared.test.ts tests/client/clan/ClanModal.rendering.test.ts tests/client/clan/ClanModal.handlers.test.ts
```

## Status

Done.

## Notes

- Shared clan helpers now compose app UI primitives for stats, pagination, search inputs, sort select, list rows, and empty states.
- Clan manage form fields now use `ui-input`, `ui-textarea`, and `ui-toggle`.
- `ui-toggle` now exposes `role="switch"` and `aria-checked` on the host so existing accessibility contracts remain visible outside shadow DOM.
- High-risk clan action buttons remain native in this pass because existing clan workflow tests target them directly; they can be migrated after adding light-DOM compatibility wrappers or updating those tests deliberately.
